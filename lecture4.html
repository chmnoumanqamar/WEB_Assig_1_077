Lecture 4: Semantic HTML5, Layout & Forms

Semantic Elements, SEO, Accessibility, Web Storage & Client Validation

Summary

This lecture transitions from basic markup to modern HTML5 semantic architecture and user data capture. It examines document flow, differentiating block-level versus inline elements, and explores the modern semantic tags that replace outdated table layouts. Students study the significant advantages of semantic markup for Search Engine Optimization (SEO) and web accessibility. The lecture also highlights HTML5 features like the <canvas> API and Web Storage (localStorage vs. sessionStorage), followed by an extensive breakdown of interactive forms, controls, input types, and robust client-side validation rules.

Topics Covered:

  • Page Layout, Flow & Content Models
    • Display Flow: Block-level elements (take full width, begin on new line) vs. Inline elements (occupy only required space)
    • Generic Containers: <div> (block wrapper) and <span> (inline wrapper)
    • HTML Content Models: Flow, phrasing, sectioning, heading, embedded, interactive, and metadata models
  • Semantic HTML5 & Structural Architecture
    • Semantic Layout Tags: <header>, <nav>, <main>, <section>, <article>, <aside>, <footer>, <figure>, and <figcaption>
    • SEO & Accessibility: Enabling search engine scrapers, screen readers (ARIA integration), and machine-readable page outlines
  • HTML5 New Features & Web Storage
    • Graphics: <canvas> API for programmatic 2D/3D dynamic rendering
    • Client Storage: localStorage (persistent key-value storage) vs. sessionStorage (tab-scoped lifecycle)
    • HTML4 vs. HTML5: Simplified doctype, audio/video native support, form validation, and cleaner syntax
  • Forms & Input Controls
    • Form Tag Attributes: <form action="url" method="GET|POST" target="_blank">
    • Form Controls: <label>, <input>, <select> (dropdowns), <textarea>, <button>, <fieldset>, and <legend>
    • Diverse Input Types: text, email, password, number, date, checkbox, radio, file, and color
    • Input Attributes: placeholder, name, value, readonly, disabled, autocomplete, autofocus, and multiple
  • Client-Side Validation & Security Considerations
    • Built-in Constraint Validation: required, pattern (regular expressions), min, max, and step
    • Client vs. Server Validation: Client-side validation improves user experience and response speed, but server-side validation is non-negotiable for security and data integrity

Example Code:

<!-- Semantic Form with Built-in Client Validation -->
<form action="/submit" method="POST">
    <fieldset style="border: 1px solid #0f766e; border-radius: 6px; padding: 14px;">
        <legend style="color: #0f766e; font-weight: bold;">User Registration</legend>
        
        <label for="username">Full Name:</label><br>
        <input type="text" id="username" name="name" placeholder="Muhammad Nouman" required><br><br>
        
        <label for="useremail">Email Address:</label><br>
        <input type="email" id="useremail" name="email" placeholder="student@example.com" required><br><br>
        
        <button type="submit">Register Now</button>
    </fieldset>
</form>

Output:

User Registration
